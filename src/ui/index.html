Settings

Saved to .env in the tool's folder. It is git-ignored: share values privately, never in the repo.

Paste a whole .env from a teammate, or copy yours to share privately. Unknown keys are kept.

How to use

1. First time

  1. Open Settings. Ask the QA lead for the values (or paste their .env in Copy / paste) and click Save.
  2. The sheet needs QA Bot (or your Checker name) in its Team tab.
  3. Click Preview on the Run tab: it lists how many checks each role has. Roles without an account are skipped.

2. Role access tests (read-only)

  1. Run tab: pick roles and environment. Leave Write results to sheet off for the first try.
  2. Click Run tests. The log shows each check; failures get a screenshot in results/.
  3. Happy with it? Run again with Write results to sheet on. Results go to the Check Log as you go.
  4. A Windows notification pops up when a run finishes, so you can work on something else.

3. Retest

  • Retest tab: Load latest results, choose Failed / Passed / Blocked, the environment and kind, then Retest these.
  • Use Failed after a bug fix. Use Passed before a release to make sure nothing broke.

4. Results summary

  • Shows pass / fail / blocked / not started per sheet and module. Click a row to list its failed tests.

5. Data tests (creates and deletes records)

  1. Set Test employee ID in Settings. Every record goes to that employee only.
  2. Pick page groups. Risky groups (rates, gov tables, payments, users, settings...) can affect everyone; they stay off unless ALLOW_RISKY_PAGES=true.
  3. Preview plan shows exactly which pages and how many records. Create test data... asks you to confirm first.
  4. Records are deleted at the end of each check. If a run was interrupted, use Clean up leftovers.
  5. .NET is locked. It only unlocks with ALLOW_DATA_ON_DOTNET=true, and every run then asks you to type DOTNET.

Statuses

  • Pass - matched the sheet's expected result. For bypass / remnant rows, Pass means the attempt was blocked.
  • Fail - check the note and screenshot: an app bug, or the runner misread the page (tell the QA lead).
  • PARTIAL in a data-test note - saved, listed and deleted, but payroll cutoff / payslip effects are not checked yet.

Command line

Everything here is also a command; each tab shows the one it runs. npm run qa -- --help style options are documented at the top of src/run.js and src/run-dp.js.
